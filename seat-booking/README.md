# 공연 좌석 예매 구현하기

순수 자바(프레임워크와 DB 없음)로 메모리에서 동작하는 공연 좌석 예매 시스템을 구현합니다.
채점은 **JUnit 테스트**로 하고, 다 만들면 미리 준비된 콘솔로 [직접 실행해 볼 수 있습니다](#직접-실행해-보기).

여러 좌석을 **한 번에, 전부 되거나 전부 안 되게** 바꾸는 문제입니다. 앞의 다섯 문제를 풀고 나서 도전해 보세요.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.seat`
- 1단계부터 차례로 구현합니다. 따로 테스트를 작성할 필요는 없고, **채점 테스트로만 확인**합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- 저장은 메모리에 합니다. 공연은 **하나**뿐이고, 예매자는 이름(문자열)으로 구분합니다.

## 1단계: 좌석과 등급

- 좌석은 **`열-번호`** 형식입니다. 열은 **`A`~`J`**(대문자), 번호는 **`1`~`10`**입니다. 모두 100석입니다.
- 형식이 틀리면 `IllegalArgumentException`이 납니다. 앞뒤 공백, 소문자, `01`처럼 0으로 시작하는 번호도 틀린 형식입니다.
- 좌석의 **등급과 가격**은 열로 정해집니다.

| 열 | 등급 | 가격 |
|---|---|---|
| A~B | `VIP` | 150,000원 |
| C~F | `R` | 100,000원 |
| G~J | `S` | 70,000원 |

| 좌석 | 결과 |
|---|---|
| `A-1`, `B-10` | `VIP`, 150,000원 |
| `C-1`, `F-7` | `R`, 100,000원 |
| `G-1`, `J-10` | `S`, 70,000원 |
| `A1`, `A-0`, `A-11`, `K-1`, `a-1`, `A-01`, ` A-1` | `IllegalArgumentException` |

## 2단계: 예매

- 예매자와 좌석 목록을 받아 예매하고 **예매 번호**를 돌려줍니다. 번호는 **1부터 하나씩** 늘어납니다.
- 예매한 좌석은 **팔린 좌석**이 됩니다.
- 예매의 **합계**는 좌석 가격을 더한 값입니다.
- 예매한 좌석 목록은 **열, 번호 순서**입니다. 번호는 숫자로 비교합니다 (`A-2`가 `A-10`보다 앞).
- 아래 경우는 `IllegalArgumentException`이 납니다.
  - 좌석이 0개이거나 5개 이상 (한 번에 **1~4석**)
  - 같은 좌석을 두 번 고름
  - 잘못된 좌석이 섞여 있음
  - 예매자가 비어 있음
- 고른 좌석 중 **하나라도 이미 팔렸으면** `IllegalStateException`이 납니다.
- **실패하면 아무 좌석도 팔리지 않고, 번호도 쓰지 않습니다.** 4석 중 3번째가 이미 팔렸어도 앞의 두 좌석은 그대로 빈 자리입니다.
- 없는 예매는 `NoSuchElementException`이 납니다.

| 동작 | 결과 |
|---|---|
| `철수`가 `A-1, C-1, G-1, J-10` | 1번, 합계 390,000원 |
| `영희`가 `B-1, A-10, A-2` | 2번, 좌석 `[A-2, A-10, B-1]` |
| `민수`가 `D-1, D-2, A-1, D-3` | `IllegalStateException`, `D-1`~`D-3`도 빈 자리 그대로 |
| `민수`가 `D-1` | 3번 (실패한 예매는 번호를 쓰지 않음) |

## 3단계: 취소와 환불

- **예매한 사람만** 예매를 취소할 수 있습니다. 다른 사람이 하면 `IllegalStateException`이 납니다.
- 취소할 때 **공연까지 남은 날**을 함께 받습니다. 환불 금액은 아래와 같습니다.

| 공연까지 남은 날 | 환불 |
|---|---|
| 3일 이상 | 전액 |
| 1~2일 | 50% |
| 0일 (당일) | 취소 불가, `IllegalStateException` |
| 음수 | `IllegalArgumentException` |

- 취소하면 그 예매의 좌석은 **다시 빈 자리**가 되고, 예매는 없는 예매가 됩니다.
- 없거나 이미 취소한 예매를 취소하면 `NoSuchElementException`이 납니다.
- 취소에 실패하면 예매와 좌석은 그대로입니다.

`A-1`(150,000원), `C-1`(100,000원)을 예매했을 때:

| 남은 날 | 환불 |
|---|---|
| 30일, 3일 | 250,000원 |
| 2일, 1일 | 125,000원 |
| 0일 | `IllegalStateException` |

## 4단계: 1인 한도와 부분 취소

**1인 한도**

- 한 사람은 **여러 번 나눠 예매해도 모두 합해 4석까지**입니다. 넘으면 `IllegalStateException`이 나고 아무 좌석도 팔리지 않습니다.
- 한도는 사람마다 따로 셉니다. 취소한 좌석은 한도에서 빠집니다.

**부분 취소**

- 예매 중 **좌석 하나만** 취소할 수 있습니다. 환불은 **그 좌석 가격**에 3단계와 같은 규칙을 적용합니다.
- 부분 취소하면 그 좌석은 빈 자리가 되고, 예매의 좌석 목록과 합계가 줄어듭니다.
- **마지막 좌석까지** 취소하면 예매가 사라집니다 (없는 예매가 됨).
- 예매에 없는 좌석을 취소하면 `IllegalArgumentException`, 다른 사람이 하면 `IllegalStateException`이 납니다.

| 동작 (모두 `철수`) | 결과 |
|---|---|
| `A-1, A-2, A-3` 예매 | 1번 |
| `B-1, B-2` 예매 | `IllegalStateException` (5석) |
| `B-1` 예매 | 2번 (딱 4석) |
| 1번 예매에서 `A-3` 취소 (5일 전) | 150,000원 환불, 1번 좌석 `[A-1, A-2]` |
| `C-1` 예매 | 3번 (다시 4석) |

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 50% 환불에서 1원 단위가 생기면 어떻게 할까요? (지금 가격으로는 생기지 않습니다)
- 부분 취소로 1석만 남은 예매를 다시 늘릴 수 있어야 할까요?
- 공연이 여러 개가 되면 좌석과 예매는 어디에 들어가야 할까요?

## 채점하기

채점 방식은 다른 문제와 같습니다. 처음이라면 [가위바위보 README의 채점하기](../rock-paper-scissors/README.md#채점하기)를 먼저 읽어 보세요.

채점 테스트는 **정해진 인터페이스(`SeatBookingApi`)만** 부르고,
각자 **`SeatBookingController`(컨트롤러)에서 그 요청을 내 코드로 넘겨 줍니다.**
두 파일은 `src/main/java/com/kdt/seat/api/`에, 채점 테스트는 `src/test/java/com/kdt/seat/grading/`에 있습니다.

```
채점 테스트 ──▶ SeatBookingApi ──────▶ SeatBookingController ──▶ 내 예매 코드
 (고정)         (고정, 인터페이스)     (내가 채움)               (설계 자유)
```

### 메서드별로 할 일

| 단계 | 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|---|
| 1 | `grade(seat)` | 좌석 등급 | `"VIP"`, `"R"`, `"S"` |
| 1 | `price(seat)` | 좌석 가격 | 원 |
| 2 | `book(customer, seats)` | 예매 | 예매 번호 |
| 2 | `total(bookingId)` | 예매 합계 | 원 |
| 2 | `isSold(seat)` | 팔린 좌석인지 | `true` / `false` |
| 2 | `seats(bookingId)` | 예매한 좌석 | 좌석 목록 (열, 번호 순) |
| 3 | `cancel(bookingId, customer, daysLeft)` | 예매 취소 | 환불 금액 |
| 4 | `cancelSeat(bookingId, customer, seat, daysLeft)` | 좌석 하나 취소 | 환불 금액 |

- **컨트롤러에는 로직을 넣지 않습니다.** 좌석 검증, 합계, 환불 계산을 여기서 하면 채점은 통과해도 예매 시스템은 구현되지 않은 것입니다.
- 채점 테스트는 테스트마다 `SeatBookingController`를 새로 만들기 때문에 매번 모든 좌석이 빈 상태에서 시작합니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 그 단계만 실패로 나옵니다.

### 실행

IntelliJ에서 `SeatBookingGradingTest`를 실행하거나:

```bash
./gradlew :seat-booking:test --tests '*GradingTest'
```

## 직접 실행해 보기

`src/main/java/com/kdt/seat/console/SeatBookingConsole.java`가 미리 들어 있습니다. 모든 단계를 구현하면 좌석표를 보면서 예매하고 취소해 볼 수 있습니다.

- 콘솔도 채점 테스트와 똑같이 `SeatBookingApi`(컨트롤러)만 부릅니다.
- 콘솔은 **채점하지 않고, 수정할 필요도 없습니다.**
- 아직 구현하지 않은 단계가 있으면 "아직 구현하지 않은 기능입니다"라고 나옵니다.

IntelliJ에서 `SeatBookingConsole`을 열고 `main` 옆의 실행 버튼을 누르거나:

```bash
./gradlew -q --console=plain :seat-booking:console
```

## 모여서 이야기할 거리

1. 좌석(`A-1`)을 객체로 만들었나요, 문자열 그대로 쓰나요? `A-2`와 `A-10`의 순서는 누가 아나요?
2. 4석 중 하나가 이미 팔렸을 때 "아무 좌석도 바뀌지 않게" 하려고 어떤 순서로 코드를 짰나요? 검증과 변경이 섞여 있지는 않나요?
3. "팔린 좌석"과 "예매에 들어 있는 좌석"을 따로 들고 있나요? 따로 들고 있다면 둘이 어긋날 수는 없나요?
4. 환불 규칙(3일 전 전액, 1~2일 전 50%)이 바뀌거나 "VIP석은 환불 50%만"이 생기면 어디를 고치나요?
5. 1인 한도 4석은 누가 확인하나요? 예매 하나는 자기 좌석만 아는데, 한도는 여러 예매를 합해야 합니다.
