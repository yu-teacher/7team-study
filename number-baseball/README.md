# 숫자 야구 구현하기

순수 자바(프레임워크 없음)로 숫자 야구 게임을 구현합니다.
입출력(콘솔, 화면) 없이 **객체와 JUnit 테스트**만으로 요구사항을 검증합니다.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.baseball`
- 1단계부터 차례로 구현하고, 요구사항마다 내 테스트를 하나 이상 작성합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.

## 1단계: 숫자 규칙

- 정답과 추측은 모두 **1~9 사이의 서로 다른 숫자 세 개**입니다.
- 규칙에 맞지 않으면 `IllegalArgumentException`이 납니다. 정답이든 추측이든 같은 규칙입니다.

| 입력 | 결과 | 이유 |
|---|---|---|
| `123`, `987`, `159` | 허용 | |
| `12`, `1234`, 빈 값 | 예외 | 세 자리가 아님 |
| `102`, `012` | 예외 | 0이 들어 있음 |
| `112`, `121`, `999` | 예외 | 같은 숫자가 있음 |
| `12a`, `abc`, `1 2`, `-12` | 예외 | 숫자가 아닌 글자가 있음 |

## 2단계: 판정

- 같은 숫자가 **같은 자리**에 있으면 **스트라이크**입니다.
- 같은 숫자가 **다른 자리**에 있으면 **볼**입니다.
- 결과는 아래 형식의 문장으로 확인할 수 있어야 합니다.
  - 스트라이크를 먼저, 볼을 나중에 쓰고, 둘 사이는 띄어 씁니다.
  - 0개인 쪽은 쓰지 않습니다. 둘 다 0개면 `낫싱`입니다.

| 정답 | 추측 | 결과 | 설명 |
|---|---|---|---|
| 123 | 123 | `3스트라이크` | 세 자리 모두 같음 |
| 123 | 124 | `2스트라이크` | 1, 2가 같은 자리 |
| 123 | 132 | `1스트라이크 2볼` | 1은 같은 자리, 3과 2는 다른 자리 |
| 123 | 913 | `1스트라이크 1볼` | 3은 같은 자리, 1은 다른 자리, 9는 없음 |
| 123 | 312 | `3볼` | 셋 다 있지만 모두 다른 자리 |
| 123 | 234 | `2볼` | 2, 3은 다른 자리, 4는 없음 |
| 123 | 456 | `낫싱` | 하나도 없음 |

## 3단계: 게임 진행

- 게임은 정답 하나를 가지고 시작하며, 상태는 **진행 중 / 승리 / 패배** 세 가지입니다.
- 추측할 때마다 **시도 횟수가 1 늘고**, 2단계의 판정 결과를 돌려줍니다.
- 규칙에 맞지 않는 추측은 예외가 나고 **시도 횟수에 들어가지 않습니다.**
- 3스트라이크면 **승리**하고 게임이 끝납니다.
- **10번** 안에 맞히지 못하면 **패배**하고 게임이 끝납니다. 10번째에 맞히면 승리입니다.
- 끝난 게임에 추측하면 `IllegalStateException`이 나고, 시도 횟수와 상태는 그대로입니다.
- **새 게임을 시작하면** 새 정답으로 바뀌고, 시도 횟수는 0, 상태는 진행 중으로 돌아갑니다.

정답이 123인 게임의 예:

| 추측 | 결과 | 시도 횟수 | 상태 |
|---|---|---|---|
| (시작) | | 0 | 진행 중 |
| 456 | `낫싱` | 1 | 진행 중 |
| 112 | `IllegalArgumentException` | 1 | 진행 중 |
| 132 | `1스트라이크 2볼` | 2 | 진행 중 |
| 123 | `3스트라이크` | 3 | 승리 |
| 456 | `IllegalStateException` | 3 | 승리 |

## 4단계: 정답 자동 생성

- 정답을 직접 주지 않아도 규칙에 맞는 정답을 **무작위로** 만들 수 있어야 합니다.
- 만들 때마다 1단계 규칙에 맞아야 하고, **매번 같은 값이면 안 됩니다.**
  - 채점 기준: 1,000번 만들었을 때 100가지 이상 나와야 합니다. (가능한 정답은 모두 504가지)
- 무작위 정답을 쓰더라도 1~3단계 테스트는 그대로 할 수 있어야 합니다.
  - 힌트: 테스트에서 "무작위"를 어떻게 정해진 값으로 바꿀 수 있을까요?

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 게임을 시작하기 전에 추측하면?
- 입력이 `null`이면?

## 채점하기

채점 방식은 신호등과 같습니다. 처음이라면 [신호등 README의 채점하기](../traffic-light/README.md#채점하기)를 먼저 읽어 보세요.

채점 테스트는 **정해진 인터페이스(`NumberBaseballDriver`)만** 부르고,
각자 **`MyNumberBaseballDriver` 한 파일에서 그 호출을 내 코드로 넘겨 줍니다.**

```
채점 테스트 ──▶ NumberBaseballDriver ──▶ MyNumberBaseballDriver ──▶ 내 숫자 야구 코드
 (고정)          (고정, 인터페이스)          (내가 채움)                 (설계 자유)
```

### 메서드별로 할 일

| 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|
| `start(answer)` | 정답을 정해서 새 게임 시작 | 없음 (규칙 위반이면 예외) |
| `guess(number)` | 추측하기 | 판정 문장. 예: `"1스트라이크 2볼"` |
| `attempts()` | 지금까지 시도 횟수 | 정수 |
| `status()` | 게임 상태 | `"PLAYING"`, `"WIN"`, `"LOSE"` |
| `randomAnswer()` | 무작위 정답 하나 만들기 | 세 자리 문자열. 예: `"582"` |

- **연결 클래스에는 로직을 넣지 않습니다.** 판정이나 검증을 여기서 하면 채점은 통과해도 숫자 야구는 구현되지 않은 것입니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 그 단계만 실패로 나옵니다.

### 실행

IntelliJ에서 `NumberBaseballGradingTest`를 실행하거나:

```bash
./gradlew :number-baseball:test --tests '*GradingTest'
```

## 모여서 이야기할 거리

1. 세 자리 숫자를 `String`, `int`, `List<Integer>` 중 무엇으로 들고 있나요? 아니면 따로 객체를 만들었나요?
2. 검증(1단계)은 어디서 하나요? 정답과 추측이 같은 검증을 공유하나요?
3. 판정 결과를 문장(`String`)으로 바로 만들었나요, 스트라이크와 볼 개수를 가진 객체로 만들었나요?
4. 4단계에서 무작위 값을 테스트하기 위해 무엇을 바꿨나요?
5. 최대 시도 횟수 10을 바꿔야 한다면 어디를 고쳐야 하나요?
