# 게시판 구현하기

순수 자바(프레임워크와 DB 없음)로 메모리에서 동작하는 게시판을 구현합니다.
입출력(콘솔, 화면) 없이 **객체와 JUnit 테스트**만으로 요구사항을 검증합니다.

글, 댓글, 작성자처럼 **여러 객체가 서로 엮이는** 문제입니다. 앞의 문제들을 풀고 나서 도전해 보세요.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.board`
- 1단계부터 차례로 구현합니다. 따로 테스트를 작성할 필요는 없고, **채점 테스트로만 확인**합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- 저장은 메모리(`List`, `Map` 등)에 합니다. 파일이나 DB는 쓰지 않습니다.
- 작성자는 이름(문자열)으로 구분합니다. 로그인이나 회원 가입은 없습니다.

## 1단계: 글 쓰기와 조회

- 글은 **작성자, 제목, 본문**을 가집니다.
- 글을 쓰면 **글 번호**를 돌려줍니다. 번호는 **1부터 하나씩** 늘어납니다.
- 규칙에 맞지 않으면 `IllegalArgumentException`이 나고, 그 글은 **번호를 쓰지 않습니다.**
  - 제목: **1자 이상 50자 이하**, 공백만 있으면 안 됨
  - 본문: 비어 있거나 공백만 있으면 안 됨
  - 작성자: 비어 있거나 공백만 있으면 안 됨
- 글 번호로 작성자, 제목, 본문을 조회할 수 있습니다.
- 없는 번호를 조회하면 `NoSuchElementException`이 납니다.

| 작성자 | 제목 | 본문 | 결과 |
|---|---|---|---|
| `철수` | `안녕하세요` | `첫 글입니다` | 1번 글 |
| `철수` | `가` (1자) | `본문` | 2번 글 |
| `철수` | `가` × 50 | `본문` | 3번 글 |
| `철수` | `가` × 51 | `본문` | `IllegalArgumentException` |
| `철수` | 빈 값, `   ` | `본문` | `IllegalArgumentException` |
| `철수` | `제목` | 빈 값, `   ` | `IllegalArgumentException` |
| 빈 값, ` ` | `제목` | `본문` | `IllegalArgumentException` |
| `철수` | `제목` | `본문` | 4번 글 (실패한 글은 번호를 쓰지 않음) |

## 2단계: 수정과 삭제

- **작성자만** 글을 수정하거나 삭제할 수 있습니다. 다른 사람이 하면 `IllegalStateException`이 나고 글은 그대로입니다.
- 수정은 제목과 본문을 바꿉니다. 작성자는 바뀌지 않습니다.
- 수정할 때도 1단계의 제목, 본문 규칙을 지켜야 합니다. 어기면 `IllegalArgumentException`이 나고 글은 그대로입니다.
- 삭제된 글은 없는 글처럼 다룹니다. 조회, 수정, 삭제하면 `NoSuchElementException`이 납니다.
- 삭제된 글의 번호는 **다시 쓰지 않습니다.**
- 글 목록은 **최신 글부터**(번호가 큰 것부터) 글 번호를 돌려줍니다. 삭제된 글은 빠집니다.

1, 2, 3번 글(작성자 `철수`)이 있을 때:

| 동작 | 결과 | 목록 |
|---|---|---|
| (처음) | | `[3, 2, 1]` |
| `영희`가 2번 삭제 | `IllegalStateException` | `[3, 2, 1]` |
| `철수`가 2번 삭제 | 삭제됨 | `[3, 1]` |
| 2번 조회 | `NoSuchElementException` | `[3, 1]` |
| 새 글 쓰기 | 4번 글 | `[4, 3, 1]` |

## 3단계: 댓글

- 글에 댓글을 달 수 있습니다. 댓글은 **작성자와 내용**을 가집니다.
- 댓글을 달면 **댓글 번호**를 돌려줍니다. 번호는 1부터, **어느 글에 달든 하나씩** 늘어납니다.
- 댓글 내용이나 작성자가 비어 있거나 공백만 있으면 `IllegalArgumentException`이 납니다.
- 없거나 삭제된 글에 댓글을 달면 `NoSuchElementException`이 납니다.
- 글의 댓글은 **먼저 단 것부터** 보이고, 댓글 수를 셀 수 있습니다.
- 댓글은 **댓글 작성자** 또는 **글 작성자**가 삭제할 수 있습니다. 그 밖의 사람이 하면 `IllegalStateException`이 납니다.
- 없거나 이미 삭제된 댓글을 삭제하면 `NoSuchElementException`이 납니다.
- 글을 삭제하면 그 글의 댓글도 함께 사라집니다.

`철수`가 쓴 1번 글에서:

| 동작 | 결과 | 댓글 |
|---|---|---|
| `영희`가 "첫 댓글" | 1번 댓글 | `["첫 댓글"]` |
| `민수`가 "두 번째 댓글" | 2번 댓글 | `["첫 댓글", "두 번째 댓글"]` |
| `민수`가 1번 댓글 삭제 | `IllegalStateException` | 그대로 |
| `영희`가 1번 댓글 삭제 | 삭제됨 (댓글 작성자) | `["두 번째 댓글"]` |
| `철수`가 2번 댓글 삭제 | 삭제됨 (글 작성자) | `[]` |

## 4단계: 목록 페이지, 검색, 조회수

**페이지**

- 목록을 **한 페이지에 10개씩**, 최신 글부터 나눠 봅니다. 페이지는 **1부터** 셉니다.
- 1보다 작은 페이지는 `IllegalArgumentException`, 글이 없는 페이지는 빈 목록입니다.
- 삭제된 글은 빠지고, 뒤의 글이 앞으로 당겨집니다.

| 상황 | 페이지 | 결과 |
|---|---|---|
| 글 25개 | 1 | `[25, 24, …, 16]` |
| 글 25개 | 2 | `[15, 14, …, 6]` |
| 글 25개 | 3 | `[5, 4, 3, 2, 1]` |
| 글 25개 | 4 | `[]` |
| 아무 때나 | 0, -1 | `IllegalArgumentException` |
| 글 11개, 11번 삭제 | 1 | `[10, 9, …, 1]` |
| 글 11개, 11번 삭제 | 2 | `[]` |

**검색**

- **제목**에 검색어가 들어간 글을 최신 글부터 찾습니다. 본문은 찾지 않습니다.
- **대소문자를 구분**합니다. 삭제된 글은 찾지 않습니다.
- 검색어가 비어 있거나 공백만 있으면 `IllegalArgumentException`이 납니다.

| 번호 | 제목 | 본문 |
|---|---|---|
| 1 | 자바 공부 | 본문 |
| 2 | 스프링 입문 | 자바 이야기 |
| 3 | 자바 스터디 모집 | 본문 |
| 4 | Java | 본문 |

| 검색어 | 결과 |
|---|---|
| `자바` | `[3, 1]` (2번은 본문에만 있음) |
| `스터디` | `[3]` |
| `java` | `[]` (대소문자가 다름) |
| `없음` | `[]` |

**조회수**

- 새 글의 조회수는 0입니다.
- 누군가 글을 **볼 때마다** 조회수가 1씩 늡니다. 같은 사람이 여러 번 봐도 매번 셉니다.
- **작성자가 자기 글을 보면** 조회수가 늘지 않습니다.
- 1단계의 작성자, 제목, 본문 조회는 "보기"가 아닙니다. 조회수에 영향을 주지 않습니다.
- 없거나 삭제된 글을 보거나 조회수를 물으면 `NoSuchElementException`이 납니다.

| 보는 사람 | 조회수 |
|---|---|
| (새 글, 작성자 `철수`) | 0 |
| `영희` | 1 |
| `영희` | 2 |
| `철수` | 2 |
| `민수` | 3 |

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 제목 앞뒤의 공백은 저장할 때 지우나요, 그대로 두나요?
- 다른 사람이 규칙에 맞지 않는 제목으로 수정하면 어떤 예외가 먼저 나나요?
- 댓글도 수정할 수 있어야 할까요?
- 삭제는 정말 지우나요, "삭제됨" 표시만 하나요? 채점 결과는 같습니다.

## 채점하기

채점 방식은 다른 문제와 같습니다. 처음이라면 [가위바위보 README의 채점하기](../rock-paper-scissors/README.md#채점하기)를 먼저 읽어 보세요.

채점 테스트는 **정해진 인터페이스(`BoardApi`)만** 부르고,
각자 **`BoardController`(컨트롤러)에서 그 요청을 내 코드로 넘겨 줍니다.**
두 파일은 `src/main/java/com/kdt/board/api/`에, 채점 테스트는 `src/test/java/com/kdt/board/grading/`에 있습니다.

```
채점 테스트 ──▶ BoardApi ────────────▶ BoardController ──▶ 내 게시판 코드
 (고정)         (고정, 인터페이스)     (내가 채움)         (설계 자유)
```

### 메서드별로 할 일

| 단계 | 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|---|
| 1 | `write(author, title, content)` | 글 쓰기 | 글 번호 |
| 1 | `title(id)`, `content(id)`, `author(id)` | 글 내용 조회 | 문자열 |
| 2 | `edit(id, editor, title, content)` | 글 수정 | 없음 |
| 2 | `delete(id, requester)` | 글 삭제 | 없음 |
| 2 | `list()` | 전체 목록 | 글 번호 목록 (최신 글부터) |
| 3 | `comment(postId, author, content)` | 댓글 달기 | 댓글 번호 |
| 3 | `comments(postId)` | 글의 댓글 | 댓글 내용 목록 (먼저 단 것부터) |
| 3 | `commentCount(postId)` | 글의 댓글 수 | 정수 |
| 3 | `deleteComment(commentId, requester)` | 댓글 삭제 | 없음 |
| 4 | `page(page)` | 페이지 목록 | 글 번호 목록 |
| 4 | `search(keyword)` | 제목 검색 | 글 번호 목록 |
| 4 | `view(id, viewer)` | 글 보기 | 없음 |
| 4 | `views(id)` | 조회수 | 정수 |

- **컨트롤러에는 로직을 넣지 않습니다.** 검증, 권한 확인, 정렬, 페이지 나누기를 여기서 하면 채점은 통과해도 게시판은 구현되지 않은 것입니다. Spring에서 컨트롤러에 비즈니스 로직을 넣지 않는 것과 같습니다.
- 채점 테스트는 테스트마다 `BoardController`를 새로 만들기 때문에 매번 빈 게시판에서 시작합니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 그 단계만 실패로 나옵니다.

### 실행

IntelliJ에서 `BoardGradingTest`를 실행하거나:

```bash
./gradlew :board:test --tests '*GradingTest'
```

## 모여서 이야기할 거리

1. 글 번호는 누가 매기나요? 글 객체인가요, 저장소인가요, 게시판인가요?
2. "작성자만 수정할 수 있다"는 확인을 글 객체가 하나요, 바깥(게시판, 서비스)이 하나요?
3. 댓글은 글 안에 들어 있나요, 따로 저장하나요? 댓글 번호로 댓글을 어떻게 찾나요?
4. 페이지 나누기와 검색은 어느 객체의 일인가요? 저장 방식이 DB로 바뀐다면 어디까지 고쳐야 하나요?
5. Spring의 Controller, Service, Repository로 나눈다면 지금 내 클래스는 각각 어디에 해당하나요?
