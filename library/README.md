# 도서 대출 구현하기

순수 자바(프레임워크와 DB 없음)로 메모리에서 동작하는 도서관 대출 시스템을 구현합니다.
채점은 **JUnit 테스트**로 하고, 다 만들면 미리 준비된 콘솔로 [직접 실행해 볼 수 있습니다](#직접-실행해-보기).

책, 회원, 대출, 예약이 **서로 엮이고**, **회원 종류마다 규칙이 다른** 문제입니다. 앞의 다섯 문제를 풀고 나서 도전해 보세요.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.library`
- 1단계부터 차례로 구현합니다. 따로 테스트를 작성할 필요는 없고, **채점 테스트로만 확인**합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- 저장은 메모리에 합니다. 회원은 이름(문자열)으로 구분합니다.

## 1단계: 책, 회원, 대출과 반납

**책과 회원**

- 책을 등록하면 **책 번호**를 돌려줍니다. 번호는 **1부터 하나씩** 늘어납니다.
- 책 제목이 비어 있거나 공백만 있으면 `IllegalArgumentException`이 나고, 번호를 쓰지 않습니다.
- 회원은 **이름과 종류**로 가입합니다. 종류는 **`NORMAL`, `STUDENT`, `STAFF`** 중 하나입니다 (대소문자 구분).
- 이름이 비어 있거나 없는 종류면 `IllegalArgumentException`, **이미 있는 이름**이면 `IllegalStateException`이 납니다.

**대출과 반납**

- 회원이 책을 빌리면 그 책은 **빌릴 수 없는 책**이 되고, 회원의 대출 목록에 들어갑니다.
- 회원의 대출 목록은 **책 번호 순서**입니다.
- 이미 빌려 간 책을 빌리면 `IllegalStateException`이 납니다.
- 반납하면 다시 빌릴 수 있는 책이 됩니다. 빌려 가지 않은 책을 반납하면 `IllegalStateException`이 납니다.
- 없는 책이나 없는 회원은 `NoSuchElementException`이 납니다.

| 동작 | 결과 | 철수의 대출 목록 |
|---|---|---|
| 책 1, 2, 3 등록 | | |
| `철수`가 3번 대출 | 3번은 빌릴 수 없음 | `[3]` |
| `철수`가 1번 대출 | | `[1, 3]` |
| `영희`가 1번 대출 | `IllegalStateException` | `[1, 3]` |
| 1번 반납 | 1번은 빌릴 수 있음 | `[3]` |

## 2단계: 회원 종류별 한도와 반납 기한

**한도와 대출 기간**

| 종류 | 최대 대출 | 대출 기간 |
|---|---|---|
| `NORMAL` | 3권 | 14일 |
| `STUDENT` | 5권 | 14일 |
| `STAFF` | 10권 | 30일 |

- 최대 권수를 넘게 빌리면 `IllegalStateException`이 납니다. 반납하면 다시 빌릴 수 있습니다.
- **반납 기한 = 빌린 날 + 대출 기간**입니다. 빌려 가지 않은 책의 기한을 물으면 `IllegalStateException`이 납니다.

**오늘 날짜**

- 도서관은 **오늘 날짜**를 압니다. 처음에는 **2026-03-01**이고, 바깥에서 바꿔 줄 수 있습니다.
- 날짜는 **`yyyy-MM-dd`** 형식입니다. 형식이 틀리거나 없는 날짜(`2026-02-30`)면 `IllegalArgumentException`이 납니다.
- 날짜는 **거꾸로 갈 수 없습니다.** 더 이른 날짜로 바꾸면 `IllegalArgumentException`이 납니다. 같은 날짜는 괜찮습니다.

| 오늘 | 회원 | 반납 기한 |
|---|---|---|
| 2026-03-01 | `NORMAL`, `STUDENT` | `2026-03-15` |
| 2026-03-01 | `STAFF` | `2026-03-31` |
| 2026-04-25 | `NORMAL` | `2026-05-09` |
| 2026-04-25 | `STAFF` | `2026-05-25` |

## 3단계: 연체

- **기한이 지난 뒤** 반납하면 **하루에 100원**씩 연체료가 붙습니다. 기한 당일 반납은 연체가 아닙니다.
- 연체료는 회원에게 쌓이고, 회원별로 **내지 않은 연체료**를 알 수 있습니다. 처음에는 0원입니다.
- 연체료를 낼 수 있습니다. 0원 이하이거나 남은 연체료보다 많으면 `IllegalArgumentException`이 나고 금액은 그대로입니다.
- 아래 회원은 **새로 빌릴 수 없습니다** (`IllegalStateException`).
  - 내지 않은 연체료가 남아 있는 회원
  - **기한이 지난 책을 아직 들고 있는** 회원 (반납 전이라 연체료는 아직 0원이어도)

기한이 2026-03-15인 책을:

| 반납한 날 | 연체료 |
|---|---|
| 2026-03-10, 2026-03-15 | 0원 |
| 2026-03-16 | 100원 |
| 2026-03-18 | 300원 |
| 2026-04-14 | 3,000원 |

## 4단계: 예약

- **대출 중인 책**은 예약할 수 있습니다. 예약한 순서대로 줄을 섭니다.
- 아래 경우는 `IllegalStateException`이 납니다.
  - 바로 빌릴 수 있는 책을 예약 (그냥 빌리면 됨)
  - 자기가 빌린 책을 예약
  - 이미 예약한 책을 또 예약
- 예약자가 있는 책이 반납되면 **첫 번째 예약자를 기다립니다.**
  - 이때 책은 "빌릴 수 있는 책"이 아닙니다.
  - 첫 번째 예약자가 아닌 사람이 빌리면 `IllegalStateException`이 납니다.
  - 첫 번째 예약자가 빌리면 예약 줄에서 빠지고, 그다음 사람이 첫 번째가 됩니다.
  - 기다리는 동안에도 다른 사람이 예약 줄 뒤에 설 수 있습니다.
- 첫 번째 예약자도 2, 3단계 규칙(한도, 연체)을 지켜야 빌릴 수 있습니다. 못 빌려도 책은 계속 그 사람을 기다립니다.
- 예약 줄은 예약자 이름 목록입니다 (먼저 한 사람부터).

| 동작 | 결과 | 1번 책 예약 줄 |
|---|---|---|
| `철수`가 1번 대출 | | `[]` |
| `영희`, `민수`가 1번 예약 | | `[영희, 민수]` |
| 1번 반납 | 빌릴 수 있는 책 아님 | `[영희, 민수]` |
| `민수`가 1번 대출 | `IllegalStateException` | `[영희, 민수]` |
| `영희`가 1번 대출 | 대출됨 | `[민수]` |

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 예약자를 기다리는 책을 며칠이 지나도 안 빌려 가면 어떻게 할까요?
- 예약을 취소할 수 있어야 할까요?
- 연체료를 일부만 낼 수 있게 한 것은 좋은 규칙일까요?

## 채점하기

채점 방식은 다른 문제와 같습니다. 처음이라면 [가위바위보 README의 채점하기](../rock-paper-scissors/README.md#채점하기)를 먼저 읽어 보세요.

채점 테스트는 **정해진 인터페이스(`LibraryApi`)만** 부르고,
각자 **`LibraryController`(컨트롤러)에서 그 요청을 내 코드로 넘겨 줍니다.**
두 파일은 `src/main/java/com/kdt/library/api/`에, 채점 테스트는 `src/test/java/com/kdt/library/grading/`에 있습니다.

```
채점 테스트 ──▶ LibraryApi ──────────▶ LibraryController ──▶ 내 도서관 코드
 (고정)         (고정, 인터페이스)     (내가 채움)           (설계 자유)
```

### 메서드별로 할 일

| 단계 | 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|---|
| 1 | `addBook(title)` | 책 등록 | 책 번호 |
| 1 | `join(member, type)` | 회원 가입 | 없음 |
| 1 | `lend(bookId, member)` | 대출 | 없음 |
| 1 | `giveBack(bookId)` | 반납 | 없음 |
| 1 | `available(bookId)` | 지금 아무나 빌릴 수 있는지 | `true` / `false` |
| 1 | `loans(member)` | 회원이 빌린 책 | 책 번호 목록 (번호 순) |
| 2 | `today(date)` | 오늘 날짜 바꾸기 | 없음 |
| 2 | `dueDate(bookId)` | 반납 기한 | `"2026-03-15"` 형식 |
| 3 | `unpaidFee(member)` | 내지 않은 연체료 | 원 |
| 3 | `pay(member, amount)` | 연체료 내기 | 없음 |
| 4 | `reserve(bookId, member)` | 예약 | 없음 |
| 4 | `reservations(bookId)` | 예약 줄 | 이름 목록 (먼저 한 사람부터) |

- **컨트롤러에는 로직을 넣지 않습니다.** 한도, 기한, 연체료, 예약 순서를 여기서 계산하면 채점은 통과해도 도서관은 구현되지 않은 것입니다.
- 채점 테스트는 테스트마다 `LibraryController`를 새로 만들기 때문에 매번 2026-03-01, 빈 도서관에서 시작합니다.
- 오늘 날짜를 `LocalDate.now()`로 구하면 채점할 수 없습니다. `today(date)`로 받은 날짜를 쓰세요.

### 실행

IntelliJ에서 `LibraryGradingTest`를 실행하거나:

```bash
./gradlew :library:test --tests '*GradingTest'
```

## 직접 실행해 보기

`src/main/java/com/kdt/library/console/LibraryConsole.java`가 미리 들어 있습니다. 모든 단계를 구현하면 책 등록, 회원 가입, 대출, 반납, 예약을 해 볼 수 있고, 날짜를 바꿔 연체도 확인할 수 있습니다.

- 콘솔도 채점 테스트와 똑같이 `LibraryApi`(컨트롤러)만 부릅니다.
- 콘솔은 **채점하지 않고, 수정할 필요도 없습니다.**
- 아직 구현하지 않은 단계가 있으면 "아직 구현하지 않은 기능입니다"라고 나옵니다.

IntelliJ에서 `LibraryConsole`을 열고 `main` 옆의 실행 버튼을 누르거나:

```bash
./gradlew -q --console=plain :library:console
```

## 모여서 이야기할 거리

1. 회원 종류별 규칙을 enum으로 만들었나요, 인터페이스와 구현 클래스로 만들었나요? "명예회원은 연체 중에도 빌릴 수 있다"가 생기면 어느 쪽이 편할까요?
2. "빌릴 수 있는가"는 책이 판단하나요, 회원이 판단하나요, 도서관이 판단하나요? 확인할 것(대출 중, 예약자, 한도, 연체)이 여러 객체에 나뉘어 있을 때 어떻게 모았나요?
3. 대출 기록(누가, 언제까지)은 책 안에 있나요, 회원 안에 있나요, 따로 있나요?
4. 연체료 계산은 누구의 일인가요? 하루 100원이 회원 종류마다 달라진다면 어디를 고치나요?
5. 오늘 날짜는 누가 들고 있나요? 회의실 예약 문제의 현재 시각과 같은 방식으로 풀었나요?
