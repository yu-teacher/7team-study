# 신호등 구현하기

순수 자바(프레임워크 없음)로 신호등을 구현합니다.
입출력(콘솔, 화면) 없이 **객체와 JUnit 테스트**만으로 요구사항을 검증합니다.

## 진행 규칙

- 패키지: `com.kdt.trafficlight`
- 단계별로 구현하고, 각 요구사항마다 테스트를 하나 이상 작성합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- 사용법 예시는 `SampleTest`를 참고하고, 구현이 시작되면 지워도 됩니다.

## 채점하기

### 왜 연결 클래스가 필요한가요?

클래스 이름과 메서드 이름은 사람마다 다릅니다. 누구는 `TrafficLight.next()`, 누구는 `Signal.change()`로 만들 수 있습니다.
채점 테스트가 특정 이름을 직접 부르면 모두가 그 이름에 맞춰야 하므로 설계가 똑같아집니다.

그래서 채점 테스트는 **정해진 인터페이스(`TrafficLightDriver`)만** 부르고,
각자 **`MyTrafficLightDriver` 한 파일에서 그 호출을 내 코드로 넘겨 줍니다.** 전기 콘센트의 변환 어댑터와 같은 역할입니다.

```
채점 테스트 ──▶ TrafficLightDriver ──▶ MyTrafficLightDriver ──▶ 내 신호등 코드
 (고정)          (고정, 인터페이스)       (내가 채움)              (설계 자유)
```

### 파일 구성

| 파일 | 역할 | 수정 |
|---|---|---|
| `grading/TrafficLightGradingTest.java` | 채점 테스트 | 하지 않음 |
| `grading/TrafficLightDriver.java` | 채점 테스트가 부르는 메서드 목록 | 하지 않음 |
| `grading/MyTrafficLightDriver.java` | 내 코드로 연결하는 곳 | **여기만 채움** |

### 메서드별로 돌려줄 값

| 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|
| `signal()` | 현재 차량 신호 | `"RED"`, `"GREEN"`, `"YELLOW"`, `"FLASHING_YELLOW"` |
| `remainingSeconds()` | 현재 신호의 남은 시간 | 초 단위 정수 |
| `pedestrianSignal()` | 현재 보행자 신호 | `"WALK"`, `"STOP"` |
| `next()` | 다음 신호로 바꾸기 | 없음 |
| `elapse(seconds)` | 시간 흐르게 하기 | 없음 |
| `pressPedestrianButton()` | 보행자 버튼 누르기 | 없음 |
| `breakDown()`, `repair()` | 고장, 복구 | 없음 |

### 채우는 예시

아래는 **신호등 문제와 상관없는 설계**를 예로 든 것입니다. 이름이 전혀 달라도 연결만 하면 된다는 것을 보여 주려는 예시이니, 이 구조를 따라 할 필요는 없습니다.

```java
public class MyTrafficLightDriver implements TrafficLightDriver {
    private final 교차로 crossroad = new 교차로();     // 1. 내 객체를 필드로 하나 만든다

    @Override
    public String signal() {
        return switch (crossroad.현재불()) {          // 2. 내 값을 정해진 문자열로 바꿔 준다
            case 빨간불 -> "RED";
            case 초록불 -> "GREEN";
            case 노란불 -> "YELLOW";
            case 점멸 -> "FLASHING_YELLOW";
        };
    }

    @Override
    public void elapse(int seconds) {
        crossroad.시간경과(seconds);                  // 3. 동작은 내 메서드를 그대로 부른다
    }

    // 나머지 메서드도 같은 방식
}
```

- 내 enum 상수 이름이 `RED`, `GREEN`처럼 영문으로 같다면 `switch` 없이 `name()`만 돌려주면 됩니다.
- 채점 테스트는 테스트마다 `MyTrafficLightDriver`를 새로 만들기 때문에, 필드에서 객체를 만들면 매번 새 신호등으로 시작합니다.
- **연결 클래스에는 로직을 넣지 않습니다.** 신호 계산을 여기서 하면 채점은 통과해도 내 신호등은 구현되지 않은 것입니다. 호출을 넘기고 값만 바꿔 주세요.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 됩니다. 그 단계만 실패로 나옵니다.

### 실행

IntelliJ에서 `TrafficLightGradingTest`를 열고 클래스 옆의 실행 버튼을 누르면 단계별로 결과가 보입니다.

```bash
./gradlew :traffic-light:test --tests '*GradingTest'
```

채점 테스트와 별개로, 내 설계에 맞는 테스트도 직접 작성해 보세요.

## 1단계: 신호 바꾸기

- 신호는 **빨강, 초록, 노랑** 세 가지입니다.
- 신호등은 처음에 **빨강**입니다.
- 다음 신호로 바꾸면 **빨강 → 초록 → 노랑 → 빨강** 순서로만 바뀝니다.
- 현재 신호를 확인할 수 있습니다.

## 2단계: 시간이 흐르면 바뀌기

- 신호마다 켜져 있는 시간이 있습니다: 빨강 30초, 초록 25초, 노랑 5초.
- 시간이 흐르면(예: "10초 경과") 신호등이 알아서 신호를 바꿉니다.
- 한 번에 여러 신호를 넘길 만큼 시간이 흐를 수 있습니다.
  - 예: 처음 빨강에서 60초가 흐르면 → 빨강 30초, 초록 25초, 노랑 5초를 모두 지나 다시 빨강, 남은 시간 30초
  - 예: 처음 빨강에서 40초가 흐르면 → 초록, 남은 시간 15초
- 현재 신호의 남은 시간을 확인할 수 있습니다.
- 1단계의 "다음 신호로 바꾸기"를 하면 바뀐 신호의 시간으로 처음부터 다시 셉니다.
- 0초 이하의 시간이 흐르는 것은 허용하지 않습니다(`IllegalArgumentException`). 이때 신호등 상태는 바뀌지 않습니다.

## 3단계: 보행자 신호

- 보행자 신호는 **건너세요 / 멈추세요** 두 가지입니다.
- 보행자 신호는 차량 신호가 **빨강일 때만** "건너세요"입니다.
- 보행자가 버튼을 누르면 차량 초록 신호의 남은 시간이 **최대 5초**로 줄어듭니다.
  - 남은 시간이 이미 5초 이하면 변화가 없습니다.
  - 초록이 아닐 때 누르면 아무 일도 일어나지 않습니다.

## 4단계 (선택): 고장 모드

- 고장 모드가 되면 신호는 **노랑 점멸**이 되고, 시간이 흐르거나 다음 신호로 바꾸려 해도 바뀌지 않습니다.
- 고장 모드에서 보행자 신호는 항상 "멈추세요"이고, 보행자 버튼도 아무 일도 하지 않습니다.
- 복구하면 **빨강**부터 처음 시간으로 다시 시작합니다.

## 모여서 이야기할 거리

1. 신호 순서(빨강 다음은 초록)는 어느 객체가 알고 있나요?
2. 신호별 시간(30, 25, 5초)은 어디에 두었나요? 바뀌어야 한다면 어디를 고쳐야 하나요?
3. 남은 시간과 현재 신호는 따로 관리하나요, 하나로 묶었나요?
4. 고장 모드를 추가할 때 기존 코드를 얼마나 고쳐야 했나요?
5. 바깥에서 신호등의 상태를 마음대로 바꿀 수 있는 방법(setter 등)이 남아 있나요?
