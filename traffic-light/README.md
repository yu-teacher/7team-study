# 신호등 구현하기

순수 자바(프레임워크 없음)로 신호등을 구현합니다.
입출력(콘솔, 화면) 없이 **객체와 JUnit 테스트**만으로 요구사항을 검증합니다.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.trafficlight`
- 1단계부터 차례로 구현합니다. 따로 테스트를 작성할 필요는 없고, **채점 테스트로만 확인**합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- JUnit 사용법은 `SampleTest`를 참고하고, 구현을 시작하면 지워도 됩니다.

## 1단계: 신호 바꾸기

- 신호는 **빨강, 초록, 노랑** 세 가지입니다.
- 신호등은 처음에 **빨강**입니다.
- "다음 신호로 바꾸기"를 하면 **빨강 → 초록 → 노랑 → 빨강** 순서로만 바뀝니다.
- 현재 신호를 확인할 수 있습니다. 확인만 해서는 신호가 바뀌지 않습니다.

| 한 일 | 현재 신호 |
|---|---|
| 처음 | 빨강 |
| 다음 신호로 1번 | 초록 |
| 다음 신호로 2번 | 노랑 |
| 다음 신호로 3번 | 빨강 |
| 다음 신호로 10번 | 초록 |

## 2단계: 시간이 흐르면 바뀌기

- 신호마다 켜져 있는 시간이 있습니다: **빨강 30초, 초록 25초, 노랑 5초**.
- 현재 신호의 **남은 시간**을 확인할 수 있습니다.
- "N초 흐르기"를 하면 남은 시간이 줄고, **남은 시간이 0이 되는 순간** 다음 신호로 바뀝니다.
- 남는 시간은 다음 신호로 이어집니다. 한 번에 여러 신호를 지나갈 수도 있습니다.

| 처음 상태에서 흐른 시간 | 현재 신호 | 남은 시간 |
|---|---|---|
| 0초 (처음) | 빨강 | 30초 |
| 10초 | 빨강 | 20초 |
| 30초 | 초록 | 25초 |
| 40초 | 초록 | 15초 |
| 55초 | 노랑 | 5초 |
| 60초 | 빨강 | 30초 |
| 607초 | 빨강 | 23초 |

- 시간을 나눠서 흘려도 결과는 같습니다. 10초 + 25초 + 10초 = 45초 → 초록, 남은 시간 10초
- 1단계의 "다음 신호로 바꾸기"를 하면 바뀐 신호의 시간으로 **처음부터 다시 셉니다**.
  - 예: 빨강에서 10초 흐른 뒤 다음 신호로 → 초록, 남은 시간 25초
- 0초 이하의 시간을 흘리면 `IllegalArgumentException`이 납니다. 이때 신호와 남은 시간은 바뀌지 않습니다.

## 3단계: 보행자 신호

- 보행자 신호는 **건너세요 / 멈추세요** 두 가지입니다.
- 차량 신호가 **빨강일 때만** "건너세요"이고, 초록과 노랑일 때는 "멈추세요"입니다.
- 보행자가 버튼을 누르면 차량 **초록** 신호의 남은 시간이 **5초로 줄어듭니다**.
  - 남은 시간이 이미 5초 이하면 그대로입니다. 버튼으로 시간이 **늘어나지는 않습니다**.
  - 빨강이나 노랑일 때 누르면 아무 일도 일어나지 않습니다.

| 상황 | 버튼 누른 뒤 |
|---|---|
| 초록, 25초 남음 | 초록, 5초 남음 |
| 초록, 6초 남음 | 초록, 5초 남음 |
| 초록, 3초 남음 | 초록, 3초 남음 |
| 초록, 25초 남음에서 버튼 3번 | 초록, 5초 남음 |
| 빨강, 20초 남음 | 빨강, 20초 남음 |

- 예: 초록에서 버튼을 누르고 5초가 흐르면 → 노랑, 남은 시간 5초

## 4단계 (선택): 고장 모드

- 고장이 나면 신호는 **노랑 점멸**이 됩니다. 어떤 신호에서 고장 나도 마찬가지입니다.
- 고장 중에는 아래가 모두 **무시**됩니다.
  - 시간 흐르기, 다음 신호로 바꾸기, 보행자 버튼
- 고장 중 보행자 신호는 항상 "멈추세요"입니다.
- 복구하면 **빨강, 남은 시간 30초**부터 다시 시작하고, 그 뒤로는 정상 동작합니다.

| 한 일 | 현재 신호 | 남은 시간 |
|---|---|---|
| 초록일 때 고장 | 노랑 점멸 | - |
| 고장 중 100초 흐르기 | 노랑 점멸 | - |
| 복구 | 빨강 | 30초 |
| 30초 흐르기 | 초록 | 25초 |

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 고장 중에 남은 시간을 물으면? (예외, 0, 그 밖의 값)
- 고장 중에 또 고장이 나면? 고장이 아닐 때 복구하면?

## 채점하기

### 왜 컨트롤러가 필요한가요?

클래스 이름과 메서드 이름은 사람마다 다릅니다. 누구는 `TrafficLight.next()`, 누구는 `Signal.change()`로 만들 수 있습니다.
채점 테스트가 특정 이름을 직접 부르면 모두가 그 이름에 맞춰야 하므로 설계가 똑같아집니다.

그래서 Spring의 컨트롤러 테스트처럼 **바깥 약속만 고정**합니다.
채점 테스트는 **정해진 인터페이스(`TrafficLightApi`)만** 부르고, 각자 **`TrafficLightController`에서 그 요청을 내 코드로 넘겨 줍니다.**
Spring 컨트롤러가 HTTP 요청을 받아 서비스로 넘기고, 결과를 응답 형식으로 바꿔 주는 것과 같은 역할입니다.

```
채점 테스트 ──▶ TrafficLightApi ─────▶ TrafficLightController ──▶ 내 신호등 코드
 (고정)         (고정, 인터페이스)     (내가 채움)                (설계 자유)
```

| Spring | 이 스터디 |
|---|---|
| HTTP 요청과 응답 형식 (고정) | `TrafficLightApi` 인터페이스 (고정) |
| 컨트롤러: 요청을 받아 서비스로 넘김 | `TrafficLightController`: 문자열과 숫자를 받아 내 객체로 넘김 |
| 서비스, 도메인 (설계 자유) | 내 신호등 코드 (설계 자유) |
| 컨트롤러 테스트 (MockMvc 등) | `TrafficLightGradingTest` |

### 파일 구성

| 파일 | 역할 | 수정 |
|---|---|---|
| `src/main/java/com/kdt/trafficlight/api/TrafficLightApi.java` | 채점 테스트가 부르는 메서드 목록 | 하지 않음 |
| `src/main/java/com/kdt/trafficlight/api/TrafficLightController.java` | 요청을 내 코드로 넘기는 컨트롤러 | **여기만 채움** |
| `src/test/java/com/kdt/trafficlight/grading/TrafficLightGradingTest.java` | 채점 테스트 | 하지 않음 |

내 신호등 코드는 `com.kdt.trafficlight` 아래에 자유롭게 만듭니다.

### 메서드별로 돌려줄 값

| 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|
| `signal()` | 현재 차량 신호 | `"RED"`, `"GREEN"`, `"YELLOW"`, `"FLASHING_YELLOW"` |
| `remainingSeconds()` | 현재 신호의 남은 시간 | 초 단위 정수 |
| `pedestrianSignal()` | 현재 보행자 신호 | `"WALK"`, `"STOP"` |
| `next()` | 다음 신호로 바꾸기 | 없음 |
| `elapse(seconds)` | 시간 흐르게 하기 | 없음 |
| `pressPedestrianButton()` | 보행자 버튼 누르기 | 없음 |
| `breakDown()`, `repair()` | 고장, 복구 | 없음 |

### 채우는 예시

아래는 **신호등 문제와 상관없는 설계**를 예로 든 것입니다. 이름이 전혀 달라도 연결만 하면 된다는 것을 보여 주려는 예시이니, 이 구조를 따라 할 필요는 없습니다.

```java
public class TrafficLightController implements TrafficLightApi {
    private final 교차로 crossroad = new 교차로();     // 1. 내 객체를 필드로 하나 만든다

    @Override
    public String signal() {
        return switch (crossroad.현재불()) {          // 2. 내 값을 정해진 문자열로 바꿔 준다
            case 빨간불 -> "RED";
            case 초록불 -> "GREEN";
            case 노란불 -> "YELLOW";
            case 점멸 -> "FLASHING_YELLOW";
        };
    }

    @Override
    public void elapse(int seconds) {
        crossroad.시간경과(seconds);                  // 3. 동작은 내 메서드를 그대로 부른다
    }

    // 나머지 메서드도 같은 방식
}
```

- 내 enum 상수 이름이 `RED`, `GREEN`처럼 영문으로 같다면 `switch` 없이 `name()`만 돌려주면 됩니다.
- 채점 테스트는 테스트마다 `TrafficLightController`를 새로 만들기 때문에, 필드에서 객체를 만들면 매번 새 신호등으로 시작합니다.
- **컨트롤러에는 로직을 넣지 않습니다.** 신호 계산을 여기서 하면 채점은 통과해도 내 신호등은 구현되지 않은 것입니다. 호출을 넘기고 값만 바꿔 주세요. Spring에서 컨트롤러에 비즈니스 로직을 넣지 않는 것과 같습니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 됩니다. 그 단계만 실패로 나옵니다.

### 실행

IntelliJ에서 `TrafficLightGradingTest`를 열고 클래스 옆의 실행 버튼을 누르면 단계별로 결과가 보입니다.

```bash
./gradlew :traffic-light:test --tests '*GradingTest'
```

## 모여서 이야기할 거리

1. 신호 순서(빨강 다음은 초록)는 어느 객체가 알고 있나요?
2. 신호별 시간(30, 25, 5초)은 어디에 두었나요? 바뀌어야 한다면 어디를 고쳐야 하나요?
3. 남은 시간과 현재 신호는 따로 관리하나요, 하나로 묶었나요?
4. 고장 모드를 추가할 때 기존 코드를 얼마나 고쳐야 했나요?
5. 바깥에서 신호등의 상태를 마음대로 바꿀 수 있는 방법(setter 등)이 남아 있나요?
