# 로또 구현하기

순수 자바(프레임워크 없음)로 로또 발급과 당첨 확인을 구현합니다.
입출력(콘솔, 화면) 없이 **객체와 JUnit 테스트**만으로 요구사항을 검증합니다.

## 진행 규칙

- 패키지: `com.kdt.lotto`
- 단계별로 구현하고, 각 요구사항마다 테스트를 하나 이상 작성합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.

## 1단계: 로또 한 장

- 로또 한 장은 **1~45 사이의 서로 다른 숫자 6개**입니다.
- 아래 경우는 허용하지 않습니다(`IllegalArgumentException`).
  - 6개가 아님
  - 1~45 범위를 벗어난 숫자가 있음
  - 같은 숫자가 있음
- 번호는 **오름차순**으로 확인할 수 있습니다. `[8, 21, 23, 41, 42, 43]`처럼 정렬된 순서입니다.

## 2단계: 당첨 번호

- 당첨 번호는 **번호 6개 + 보너스 번호 1개**입니다.
- 번호 6개는 1단계 규칙을 따릅니다.
- 보너스 번호도 1~45 사이여야 하고, **번호 6개와 겹치면 안 됩니다**(`IllegalArgumentException`).

## 3단계: 등수와 상금

내 로또와 당첨 번호를 비교해 등수를 정합니다.

| 등수 | 조건 | 상금 |
|---|---|---|
| 1등 | 6개 일치 | 2,000,000,000원 |
| 2등 | 5개 일치 + 보너스 번호 일치 | 30,000,000원 |
| 3등 | 5개 일치 | 1,500,000원 |
| 4등 | 4개 일치 | 50,000원 |
| 5등 | 3개 일치 | 5,000원 |
| 꽝 | 2개 이하 일치 | 0원 |

- 보너스 번호는 **5개 일치일 때만** 의미가 있습니다. 4개 일치 + 보너스 일치는 그냥 4등입니다.

## 4단계: 구매와 수익률

- 로또 한 장은 **1,000원**입니다. 금액을 내면 그만큼 **자동(무작위)으로** 발급합니다.
  - 예: 14,000원 → 14장
- 아래 금액은 허용하지 않습니다(`IllegalArgumentException`).
  - 1,000원 미만
  - 1,000원 단위가 아님 (예: 1,500원)
  - 100,000원 초과 (1회 구매 한도)
- 여러 장의 결과로 **수익률**을 계산합니다.
  - 수익률(%) = 총 상금 ÷ 구입 금액 × 100, **소수 둘째 자리에서 반올림**
  - 예: 8장(8,000원) 중 5등 1장 → 5,000 ÷ 8,000 × 100 = **62.5**
  - 예: 3장(3,000원) 중 5등 1장 → 166.666... → **166.7**

## 채점하기

### 왜 연결 클래스가 필요한가요?

클래스 이름과 메서드 이름은 사람마다 다릅니다.
채점 테스트는 **정해진 인터페이스(`LottoDriver`)만** 부르고,
각자 **`MyLottoDriver` 한 파일에서 그 호출을 내 코드로 넘겨 줍니다.**

```
채점 테스트 ──▶ LottoDriver ──▶ MyLottoDriver ──▶ 내 로또 코드
 (고정)          (고정)          (내가 채움)        (설계 자유)
```

### 메서드별로 할 일

| 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|
| `ticket(numbers)` | 번호로 로또 한 장 만들기 | 오름차순 번호 목록 |
| `winning(numbers, bonus)` | 당첨 번호 정하기 | 없음 |
| `rank(numbers)` | 이 번호의 등수 | `"FIRST"`, `"SECOND"`, `"THIRD"`, `"FOURTH"`, `"FIFTH"`, `"NONE"` |
| `prize(numbers)` | 이 번호의 상금 | 원 단위 정수 (`long`) |
| `buyAuto(money)` | 금액만큼 자동 발급 | 로또 번호 목록들 |
| `profitRate(tickets)` | 여러 장의 수익률 | 예: `62.5` |

- `rank`, `prize`, `profitRate`는 `winning`으로 당첨 번호를 정한 뒤에 불립니다.
- `profitRate`의 구입 금액은 장수 × 1,000원입니다.
- **연결 클래스에는 로직을 넣지 않습니다.** 판정, 검증, 계산을 여기서 하면 채점은 통과해도 로또는 구현되지 않은 것입니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 그 단계만 실패로 나옵니다.
- 사용 예시는 [신호등 README](../traffic-light/README.md#채우는-예시)를 참고하세요.

### 실행

IntelliJ에서 `LottoGradingTest`를 실행하거나:

```bash
./gradlew :lotto:test --tests '*GradingTest'
```

## 모여서 이야기할 거리

1. 숫자 하나(1~45)를 `int`로 썼나요, 객체로 만들었나요? 각각 장단점은?
2. 로또 번호 6개를 `List`와 `Set` 중 무엇으로 들고 있나요? 정렬은 언제 하나요?
3. 바깥에서 넘겨받은 리스트를 나중에 바깥에서 바꾸면 내 로또 번호도 바뀌나요? 내가 돌려준 목록을 바깥에서 바꿀 수 있나요?
4. 등수 판정(`if` 여러 개)을 어디에 두었나요? 등수와 상금을 같이 묶었나요?
5. 6등(2개 일치, 1,000원)이 새로 생긴다면 몇 군데를 고쳐야 하나요?
6. 자동 발급을 어떻게 테스트했나요?
