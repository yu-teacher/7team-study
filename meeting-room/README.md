# 회의실 예약 구현하기

순수 자바(프레임워크와 DB 없음)로 메모리에서 동작하는 회의실 예약 시스템을 구현합니다.
채점은 **JUnit 테스트**로 하고, 다 만들면 미리 준비된 콘솔로 [직접 실행해 볼 수 있습니다](#직접-실행해-보기).

**시간대라는 값**과 **"지금 몇 시인가"라는 바깥 정보**를 다루는 문제입니다. 앞의 다섯 문제를 풀고 나서 도전해 보세요.

> 처음이라면 [루트 README](../README.md#진행-방법)에서 브랜치 만드는 법부터 보세요.

## 진행 규칙

- 패키지: `com.kdt.meetingroom`
- 1단계부터 차례로 구현합니다. 따로 테스트를 작성할 필요는 없고, **채점 테스트로만 확인**합니다.
- 클래스 이름, 메서드 이름, 구조는 자유입니다. 설계 차이를 비교하는 것이 목적입니다.
- 저장은 메모리에 합니다. 날짜는 다루지 않고 **오늘 하루**만 예약합니다.
- 회의실은 **`A`, `B`, `C`** 세 곳입니다. 예약자는 이름(문자열)으로 구분합니다.

## 1단계: 시간대

- 시각은 **`HH:mm`** 형식입니다. 시와 분은 꼭 두 자리입니다 (`09:00`은 되고 `9:00`은 안 됨).
- 예약하는 시간대(시작~끝)는 아래 규칙을 지켜야 합니다. 어기면 `IllegalArgumentException`이 납니다.
  - **30분 단위**: 분은 `00` 또는 `30`
  - **운영 시간 09:00~18:00** 안: 시작은 09:00 이후, 끝은 18:00 이전
  - **시작이 끝보다 빨라야** 함 (같아도 안 됨)
- 시간대의 길이를 **분**으로 알 수 있습니다.
- 두 시간대가 **겹치는지** 알 수 있습니다. **끝과 시작이 맞닿기만 하면 겹치지 않습니다.**

| 시작 | 끝 | 결과 |
|---|---|---|
| `10:00` | `11:00` | 60분 |
| `13:30` | `15:00` | 90분 |
| `09:00` | `18:00` | 540분 |
| `10:15` | `11:00` | `IllegalArgumentException` (30분 단위 아님) |
| `08:30` | `10:00` | `IllegalArgumentException` (09:00 전) |
| `17:00` | `18:30` | `IllegalArgumentException` (18:00 뒤) |
| `11:00` | `10:00`, `11:00` | `IllegalArgumentException` (시작이 늦거나 같음) |
| `9:00`, `25:00`, `10:60`, `ab:cd` | | `IllegalArgumentException` (형식이 틀림) |

| 시간대 1 | 시간대 2 | 겹치는가 |
|---|---|---|
| 10:00~11:00 | 10:30~11:30 | 예 |
| 10:00~12:00 | 10:30~11:00 | 예 (안에 들어감) |
| 10:00~11:00 | 10:00~11:00 | 예 (같음) |
| 10:00~11:00 | 11:00~12:00 | **아니요** (맞닿기만 함) |
| 10:00~11:00 | 14:00~15:00 | 아니요 |

## 2단계: 예약

- 회의실, 예약자, 시작, 끝을 받아 예약하고 **예약 번호**를 돌려줍니다. 번호는 **1부터 하나씩** 늘어납니다.
- **같은 회의실**에서 이미 있는 예약과 겹치면 `IllegalStateException`이 납니다. 다른 회의실은 상관없습니다.
- 없는 회의실(`D`, `a` 등)이나 빈 예약자는 `IllegalArgumentException`이 납니다. 1단계의 시간 규칙도 지켜야 합니다.
- 실패한 예약은 **번호를 쓰지 않습니다.**
- 회의실 일정은 **시작 시각 순서로** `"시작-끝 예약자"` 형식의 문자열 목록입니다.

| 동작 | 결과 | A 일정 |
|---|---|---|
| `철수`가 A 14:00~15:00 | 1번 | `["14:00-15:00 철수"]` |
| `영희`가 A 10:00~10:30 | 2번 | `["10:00-10:30 영희", "14:00-15:00 철수"]` |
| `민수`가 A 14:30~15:30 | `IllegalStateException` | 그대로 |
| `민수`가 A 15:00~16:00 | 3번 (맞닿기만 함) | 세 개 |
| `민수`가 B 14:00~15:00 | 4번 (다른 회의실) | 그대로 |

## 3단계: 현재 시각과 취소

**현재 시각**

- 시스템은 **현재 시각**을 압니다. 처음에는 **09:00**이고, 바깥에서 바꿔 줄 수 있습니다.
- 현재 시각도 `HH:mm` 형식입니다. 30분 단위나 운영 시간 규칙은 없습니다 (`10:15`, `20:00`도 됨).
- 현재 시각은 **거꾸로 갈 수 없습니다.** 더 이른 시각으로 바꾸면 `IllegalArgumentException`이 납니다.
- **시작이 현재 시각보다 이른** 예약은 `IllegalStateException`이 납니다. 시작이 현재 시각과 **같으면** 예약할 수 있습니다.

| 현재 시각 | 예약 시간대 | 결과 |
|---|---|---|
| 09:00 (처음) | 09:00~10:00 | 예약됨 |
| 10:15 | 10:00~11:00 | `IllegalStateException` (이미 시작함) |
| 10:00 | 10:00~11:00 | 예약됨 (지금 시작) |

**취소**

- **예약한 사람만** 취소할 수 있습니다. 다른 사람이 하면 `IllegalStateException`이 나고 예약은 그대로입니다.
- **시작 시각이 되었거나 지난** 예약은 취소할 수 없습니다 (`IllegalStateException`).
- 취소한 예약은 일정에서 빠지고, 그 시간을 다른 사람이 다시 예약할 수 있습니다.
- 없거나 이미 취소한 예약을 취소하면 `NoSuchElementException`이 납니다.

10:00~11:00 예약(예약자 `철수`)이 있을 때:

| 현재 시각 | 취소하는 사람 | 결과 |
|---|---|---|
| 09:00 | `영희` | `IllegalStateException` |
| 09:59 | `철수` | 취소됨 |
| 10:00 | `철수` | `IllegalStateException` (시작함) |

## 4단계: 한 사람의 하루 한도

- 한 사람은 하루에 **모든 회의실을 합해 2시간(120분)까지** 예약할 수 있습니다. 넘으면 `IllegalStateException`이 납니다.
- 취소한 예약은 한도에 들어가지 않습니다. 이미 끝난 예약은 들어갑니다.
- 한 사람이 **같은 시간에 두 회의실**을 잡을 수는 없습니다 (`IllegalStateException`).
- 한 사람이 오늘 예약한 시간을 **분**으로 알 수 있습니다. 예약이 없으면 0, 빈 이름은 `IllegalArgumentException`입니다.

| 동작 (모두 `철수`) | 결과 | 사용 시간 |
|---|---|---|
| (처음) | | 0분 |
| A 10:00~11:00 | 예약됨 | 60분 |
| B 10:30~11:00 | `IllegalStateException` (A와 같은 시간) | 60분 |
| B 13:00~13:30 | 예약됨 | 90분 |
| C 15:00~16:00 | `IllegalStateException` (150분) | 90분 |
| C 15:00~15:30 | 예약됨 (딱 120분) | 120분 |

## 정해지지 않은 것 (자유)

아래는 채점하지 않으니 자유롭게 정하고, 왜 그렇게 정했는지 이야기해 보세요.

- 같은 사람이 같은 회의실을 이어서(10:00~11:00, 11:00~12:00) 예약하면 하나로 합쳐야 할까요?
- 예약 번호는 회의실마다 따로 매기는 게 나을까요, 전체에서 하나로 매기는 게 나을까요?
- 겹치는 예약과 한도 초과가 동시에 해당되면 어떤 메시지가 먼저 나와야 할까요?

## 채점하기

채점 방식은 다른 문제와 같습니다. 처음이라면 [가위바위보 README의 채점하기](../rock-paper-scissors/README.md#채점하기)를 먼저 읽어 보세요.

채점 테스트는 **정해진 인터페이스(`MeetingRoomApi`)만** 부르고,
각자 **`MeetingRoomController`(컨트롤러)에서 그 요청을 내 코드로 넘겨 줍니다.**
두 파일은 `src/main/java/com/kdt/meetingroom/api/`에, 채점 테스트는 `src/test/java/com/kdt/meetingroom/grading/`에 있습니다.

```
채점 테스트 ──▶ MeetingRoomApi ──────▶ MeetingRoomController ──▶ 내 회의실 코드
 (고정)         (고정, 인터페이스)     (내가 채움)               (설계 자유)
```

### 메서드별로 할 일

| 단계 | 메서드 | 할 일 | 돌려줄 값 |
|---|---|---|---|
| 1 | `minutes(start, end)` | 시간대 길이 | 분 |
| 1 | `overlaps(start1, end1, start2, end2)` | 두 시간대가 겹치는지 | `true` / `false` |
| 2 | `reserve(room, member, start, end)` | 예약 | 예약 번호 |
| 2 | `schedule(room)` | 회의실 일정 | `"10:00-11:00 철수"` 형식 목록 (시작 순) |
| 3 | `now(time)` | 현재 시각 바꾸기 | 없음 |
| 3 | `cancel(reservationId, member)` | 예약 취소 | 없음 |
| 4 | `usedMinutes(member)` | 오늘 예약한 시간 | 분 |

- **컨트롤러에는 로직을 넣지 않습니다.** 시간 검증, 겹침 확인, 한도 계산을 여기서 하면 채점은 통과해도 회의실 예약은 구현되지 않은 것입니다.
- 채점 테스트는 테스트마다 `MeetingRoomController`를 새로 만들기 때문에 매번 09:00, 빈 일정에서 시작합니다.
- 아직 구현하지 않은 단계의 메서드는 `throw`를 그대로 두면 그 단계만 실패로 나옵니다.

### 현재 시각은 어디서 오나요?

`LocalTime.now()`를 도메인 코드 안에서 바로 부르면, 테스트를 돌리는 시각에 따라 결과가 달라져서 채점할 수 없습니다.
그래서 이 문제는 **`now(time)`으로 바깥에서 현재 시각을 정해 줍니다.**
"지금 몇 시인지"를 누가 들고 있고, 예약 규칙은 그 값을 어떻게 받아서 쓰는지 직접 설계해 보세요. 수업에서 다룬 DIP와 이어지는 부분입니다.

### 실행

IntelliJ에서 `MeetingRoomGradingTest`를 실행하거나:

```bash
./gradlew :meeting-room:test --tests '*GradingTest'
```

## 직접 실행해 보기

`src/main/java/com/kdt/meetingroom/console/MeetingRoomConsole.java`가 미리 들어 있습니다. 모든 단계를 구현하면 예약, 일정 보기, 취소를 해 볼 수 있고, "시간 흐르기"로 현재 시각을 바꿔 볼 수 있습니다.

- 콘솔도 채점 테스트와 똑같이 `MeetingRoomApi`(컨트롤러)만 부릅니다.
- 콘솔은 **채점하지 않고, 수정할 필요도 없습니다.**
- 아직 구현하지 않은 단계가 있으면 "아직 구현하지 않은 기능입니다"라고 나옵니다.

IntelliJ에서 `MeetingRoomConsole`을 열고 `main` 옆의 실행 버튼을 누르거나:

```bash
./gradlew -q --console=plain :meeting-room:console
```

## 모여서 이야기할 거리

1. 시간대(시작~끝)를 객체로 만들었나요, `LocalTime` 두 개를 따로 들고 다니나요? 겹침 판정은 누구의 일인가요?
2. 현재 시각은 누가 들고 있나요? 예약 규칙 코드가 `LocalTime.now()`를 직접 부르고 있지는 않나요?
3. "같은 회의실에서 겹치면 안 된다"와 "한 사람이 같은 시간에 두 곳에 있으면 안 된다"는 같은 곳에서 확인하나요?
4. 하루 한도 2시간이 직급마다 달라진다면 어디를 고쳐야 하나요?
5. 날짜가 추가되어 "다음 주 예약"도 받아야 한다면 어디까지 바뀌나요?
